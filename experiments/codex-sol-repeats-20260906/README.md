# Codex / Sol: повторные эксперименты V2/V3

Отдельный набор для внутреннего понимания вариативности, не для текущей статьи.
План: десять полных попыток каждого режима на пяти прежних проектах, всего 100 новых запусков задач.
Начало 2026-09-05 UTC / 2026-09-06 Europe/Moscow. Максимум пять основных CLI одновременно.
Серия завершена: 100/100 запусков, финальный аудит пройден. [Итоги и интерпретация](./RESULTS.md).

- [Условия](./PROTOCOL.md), [зафиксированные хеши](./source-manifest.json).
- [Состояние запуска и номера исходных серий](./run.json).
- [Отчёт](./REPORT.md), [данные отдельных задач](./data.json), [распределения и парные сравнения](./statistics.json).
- `usage-audit.json`: независимый пересчёт input/output/обращений по исходным журналам.
- `AUXILIARY-USAGE.md` и `auxiliary-usage.json`: отдельный учёт связанных вспомогательных моделей после сбора.
- `trace-audit.json`: проверка записанных статусов батчей, не повторное исполнение действий.
- `action-errors.json`: ретроспективная классификация сообщений об ошибках действий по текстовым маркерам;
  это ориентир для диагностики, а не доказательство причины каждого сбоя.
- `artifact-scan.json`: эвристический скан открытых текстовых полей, не разрешение на публикацию.
- [Замечание к оценщику CLI](./EVALUATOR-NOTE.md): исходные баллы сохраняются, дополнительная проверка удаления
  на копиях проектов показана отдельно как анализ чувствительности качества.

Пока `data.json.missing > 0`, все агрегаты предварительные. Ошибки моделей не перепрогоняются автоматически.
Сырые журналы находятся в новых сериях `experiments/codex-skill-state/results/`, перечисленных в `run.json`.
Созданные проекты сохраняются рядом с ними после внешней оценки; большие файлы, зависимости и потенциальные
конфигурации с секретами исключаются с явным описанием в `workspace-manifest.json`.

## Анализ без повторного вызова моделей

```sh
bun experiments/codex-sol-repeats-20260906/analyze.ts
bun experiments/codex-sol-repeats-20260906/archive-workspaces.ts
bun experiments/codex-sol-repeats-20260906/audit-traces.ts
bun experiments/codex-sol-repeats-20260906/action-errors.ts
bun experiments/codex-sol-repeats-20260906/host-context-audit.ts
bun experiments/codex-sol-repeats-20260906/auxiliary-usage.ts
bun experiments/codex-sol-repeats-20260906/scan-artifacts.ts
bun experiments/codex-sol-repeats-20260906/audit-taskboard-delete.ts
bun experiments/codex-sol-repeats-20260906/analyze.ts --final
bun experiments/codex-sol-repeats-20260906/verify.ts
```

Финальные проверки требуют 100 завершённых ячеек без расхождений usage, проверяют хеши архивов, не более пяти
пересекающихся интервалов runner, неизменность исходников, статьи и всего её экспериментального пакета относительно
начала этой серии. Итог записывается в `verification.json`. Запуск `run.ts` второй раз запрещён
самим скриптом: сначала нужно разобраться в существующем состоянии, а не перезаписывать его.

Обращения, input основного цикла и вспомогательных моделей — разные показатели; токены не переводятся в деньги.
Пять проектов, повторённых десять раз, не дают пятидесяти независимых задач. Данные статьи не изменяются.
