# Astra / SKILL.state с лимитами 2 MiB

Отдельная серия после [чистой Astra](../codex-astra-repeats-20260908/PROTOCOL.md):
четыре режима, пять повторов пяти проектов, до пяти CLI одновременно.
Статья и прежние результаты не меняются.

Основной документ — [протокол](PROTOCOL.md). Особенность этой серии —
увеличение четырёх лимитов SKILL.state плюс сохранение целого JSON перехода
при записи в историю. Это совместная проверка изменений, не их отдельные абляции.
Штатные ограничения инструментов и провайдера остаются.

## Материалы

- [Изменения ядра и тесты](kernel.patch): применяются поверх commit 85630a5b
  из корня отдельного checkout репозитория.
- [Происхождение сборки](build-manifest.json) и [локальные проверки](preflight.json).

- [Расписание и текущее состояние](run.json) обновляются оркестратором.
- По завершении: restoration.json и isolation-watch.json подтверждают
  возврат глобальных источников и проверки изоляции.
- Приватные summary, events, rollout, context-budget-audit и отпечатки
  начальных сообщений сохраняются в .private/results.

Старый codex/codex-rs/target/debug/codex не перезаписывается.
Новый бинарник собирается в .private/source/codex/codex-rs/target/debug/codex.
Рабочая копия — detached sparse git worktree, а не изменение основного ядра.

## Управление

Новый запуск после успешных проверок и фиксации build-manifest:

```sh
bun experiments/codex-astra-large-context-20260908/run.ts --with-global-instructions
```

Оркестратор откажется перезаписывать уже существующую серию. Не удаляйте
run.json или source-manifest ради повторного запуска.

Числовой статус без вывода промптов:

```sh
bun experiments/codex-astra-large-context-20260908/progress.ts
```

Глобальные sources возвращаются в finally после завершения воркеров.
После жёсткого прерывания сначала убедитесь, что воркеры остановлены,
затем используйте приватный указатель .private/isolation.json и команду
isolation.ts restore с точным путём ledger. Резервные копии не удалять.

Сырые логи и workspace не публикуются автоматически. Итоговые сравнения
должны отдельно показать качество артефактов, штатное завершение, таймауты,
токены и циклы, а также сколько обрезок фактически осталось.
