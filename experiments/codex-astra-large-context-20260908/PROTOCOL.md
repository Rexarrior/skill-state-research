# Astra: большие лимиты SKILL.state

Протокол зафиксирован до вызовов модели, 2026-09-08.
Это новая серия, а не замена прежних результатов и не обновление статьи.

## Что проверяем

В чистой серии Astra state-режимы нередко повторно читали уже созданный код.
Проверяем, изменится ли поведение, если почти убрать нашу дополнительную обрезку:

| Ограничение SKILL.state | Чистая Astra | Новая серия |
|---|---:|---:|
| Полный JSON state | 32 KiB | 2 MiB |
| JSON входа одного принимаемого действия | 64 KiB | 2 MiB |
| JSON входа действия в observation | 3 KiB | 2 MiB |
| Результат одного действия в observation | 4 KiB | 2 MiB |

2 MiB = 2 097 152 байта. Это четыре отдельных ограничения, **не общий бюджет
промпта** и не размер окна модели. Комментарий по-прежнему ограничен 1 KiB.
К результату на границе добавляется прежний маркер обрезки; он может выходить
за лимит на несколько десятков байтов. Вход действия проверяется вместе с JSON-обвязкой.

Paper сохраняет только последнее O и прежнюю семантику patch; V2/V3 — k=3.
В V3 один батч по-прежнему занимает один слот; число действий не ограничено.
Поэтому 2 MiB на результат не означает 2 MiB на батч или на весь запрос.
Схемы инструментов, текст протокола, порядок валидации, модели владения state
и критерий finish не меняются.

Есть необходимая сопутствующая поправка: JSON перехода записывается с размерным
исключением из повторной обрезки истории. Иначе обычная обрезка tool output
может разрезать уже ограниченный контейнер, после чего snapshot нельзя прочитать.
Это только внутренняя history metadata; в промпт она не добавляется.
Поправка покрывает и принятые, и отклонённые переходы, включая восстановление.
Native этой веткой не пользуется.

Лимиты самих инструментов, явно запрошенный моделью max_output_tokens, буферы
процессов, ограничения провайдера и штатный native context management не меняются.
Например, exec_command с указанным max_output_tokens может обрезать вывод ещё
до SKILL.state. Новая серия не обещает полностью необрезанный контекст.

Это экспериментальное исключение из обычных рекомендаций Codex по небольшим
элементам контекста, прямо запрошенное пользователем. Крупные элементы проверяем
локальными тестами до модели. Провайдер всё ещё может отказать слишком большому
запросу: такие ошибки сохраняются, а не маскируются повтором.

## Условия

- gpt-6-astra, reasoning medium; та же авторизация, без сбросов лимитов.
- Native / Paper / V2 / V3: пять повторов пяти прежних проектов, всего 100 сессий.
- До пяти основных CLI одновременно; permission reviewer остаётся включён.
- Таймаут 900 000 мс, те же one-shot инструкции, SPEC и независимый оценщик.
- То же заранее определённое чередование, что в чистых сериях Astra и Sol.
- Все четыре режима работают на одной отдельной сборке. Старый бинарник
  и исходники остаются неизменными; patch и отпечатки новой сборки сохраняются.
  Code Mode companion берётся из прежней сборки с проверкой SHA-256.
- Новые каталоги и идентификаторы сессий; никаких автоматических outcome retries.
  Ошибки авторизации/лимитов, отсутствие usage и загрязнение контекста
  останавливают новые запуски. Обычные таймауты и неуспешные решения учитываются.

## Изоляция

Повторяем проверенную чистую Sol: временно перемещаем глобальные skills,
skills в кэше плагинов и глобальные AGENTS.md / AGENTS.override.md.
Авторизацию и конфигурацию не редактируем. Сохраняем приватный write-ahead журнал,
права и отпечатки; возвращаем всё после завершения воркеров, включая ошибки
и обрабатываемые сигналы. Новые файлы на прежних местах сохраняем отдельно.

Сохраняются --ignore-user-config, --ignore-rules, отключённый skill_search,
skills.include_instructions=false, skills.bundled.enabled=false,
project_doc_max_bytes=0 и прежний --approve-for-me.
Проверка источников — перед запуском, после исхода и каждые две секунды.
Разрешено повторное появление только отключённого скрытого .system-кэша
в обычном каталоге ~/.codex/skills; активные источники и ссылки запрещены.
Проверяем начальные сообщения rollout на каталоги скиллов и глобальный профиль.
Это аудит записанного контекста, не перехват всех сетевых пакетов.

После SIGKILL/перезагрузки восстановление выполняется по указателю
.private/isolation.json. Нельзя просто запускать серию заново поверх run.json.

## Что сохраняем и как сравниваем

Отдельно по каждому исходу: input (включая cached), output, число ответов модели,
время, таймауты, исходные assertions, finish/turn.completed.
Полный успех требует и корректного артефакта, и штатного завершения протокола.
Вспомогательные вызовы учитываются отдельно от main; время таймаута не называем
временем решения. Известную проверку taskboard delete применяем отдельно
на копиях всех CLI-артефактов, не меняя исходных оценок.

Дополнительно считаем размеры state, сохранённых входов и результатов,
маркеры обрезки SKILL.state и более ранней обрезки инструментов.
Сверяем фактическую модель и числовые usage-записи с итоговым summary.

Внутри новой серии сравниваем четыре режима. С прежней чистой Astra —
отдельные когорты одинакового размера, без выборочного исключения таймаутов.
Сразу изменены четыре лимита и защита JSON от повторной обрезки: результат
нельзя приписывать каждому изменению по отдельности. Дата, нагрузка и случайность
также не разделены контролируемой абляцией. Новая native-серия нужна как контроль.

## Локальные проверки перед запуском

- Большие state, input и result проходят admission, историю и provider_input.
- JSON metadata сохраняется при сериализации/восстановлении.
- Превышение 2 MiB отклоняется атомарно; UTF-8 обрезается корректно.
- Native tool outputs не получают нового исключения.
- CLI mock-provider получает полный state и большое сообщение об отклонении
  действия выше прежних лимитов во всех трёх state-режимах.
  Отдельный CLI-тест большого обычного shell output оставлен с явным ignore:
  managed approval service этого хоста отклоняет команды mock-provider.
  Эта граница проверена unit-тестом перехода с большим ActionOutcome,
  но полный shell → CLI → provider путь локальной фикстуры здесь не подтверждён.
  В настоящей серии дополнительно аудируем сохранённые размеры и обрезки.
- Проверки расписания, неизменности runner-контракта, изоляции и worker pool.
- doctor и отпечатки основного бинарника и companion.

Сырые логи и отдельный worktree хранятся в игнорируемой .private/.
Публикация результатов — отдельный очищенный снимок после серии.
