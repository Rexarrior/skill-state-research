# Что проверяет оценщик

Этот документ описывает внешние проверки пяти codegen-задач из эксперимента.
Агент получает только спецификацию проекта и пустую рабочую папку. Код оценщика
находится за её пределами и запускается после завершения сессии.

Авторитетным источником остаётся
[`scripts/evaluate.ts`](./scripts/evaluate.ts). Здесь его проверки пересказаны
человеческим языком.

Каждая проверка даёт один балл. Во всех пяти задачах последний балл начисляется
за непустой `README.md` длиной не менее 80 символов. Поэтому количество
функциональных проверок на единицу меньше итогового максимума.

## Taskboard CLI

[Спецификация](./projects/taskboard-cli/SPEC.md) ·
[код проверок](./scripts/evaluate.ts#L80)

1. **Добавление, нормализация и сохранение.** Первая задача получает `id=1`,
   статус `open`, переданный срок и корректный `createdAt`. Теги проверяются
   без учёта регистра, повторы должны удаляться. После повторного запуска
   следующая задача получает `id=2`, то есть данные действительно сохраняются.
2. **Совместная фильтрация списка.** Фильтры по статусу и тегу применяются
   одновременно; регистр тега не влияет на результат.
3. **Идемпотентный `done`.** Повторное завершение одной задачи успешно и не
   меняет уже установленный `completedAt`.
4. **Удаление и отсутствующие идентификаторы.** Существующая задача удаляется,
   обращение к неизвестному `id` завершается ошибкой.
5. **Просроченные задачи и статистика.** Фильтр `--overdue` возвращает
   ожидаемую задачу, а `stats` правильно считает общее число, открытые,
   завершённые и просроченные задачи.
6. **Некорректная дата не меняет данные.** Невозможная календарная дата
   отклоняется, содержимое базы остаётся побайтно прежним.
7. **Повреждённая база не перезаписывается.** Некорректный JSON приводит к
   ошибке, исходный повреждённый файл сохраняется без изменений.
8. **README.** В проекте есть содержательный `README.md`.

## CSV Insights

[Спецификация](./projects/csv-insights/SPEC.md) ·
[код проверок](./scripts/evaluate.ts#L157)

1. **Разбор CSV и совместные фильтры.** Поддерживаются CSV-поля с запятыми и
   переводами строк по правилам RFC; несколько `--where` работают одновременно.
2. **Сумма и среднее.** После фильтрации и группировки правильно вычисляются
   `sum` и `avg`; десятичные значения выводятся без ошибок двоичной
   арифметики и лишних нулей.
3. **Корректный CSV-вывод.** Фильтр не теряется при выборе CSV-формата, а поле с
   переводом строки остаётся правильно заключённым в кавычки.
4. **Неизвестная колонка.** Фильтр по отсутствующей колонке завершается ошибкой,
   которая указывает на проблему с колонкой.
5. **Некорректное число.** Нечисловая ячейка в агрегируемом столбце отклоняется;
   сообщение сообщает имя столбца и номер строки.
6. **Строки разной длины.** Запись с недостающим числом полей считается
   ошибочной.
7. **Исходный файл не меняется.** Анализ не модифицирует входной CSV.
8. **README.** В проекте есть содержательный `README.md`.

## Mini Template

[Спецификация](./projects/mini-template/SPEC.md) ·
[код проверок](./scripts/evaluate.ts#L227)

1. **Подстановки, экранирование и комментарии.** Обычная подстановка экранирует
   HTML, тройные фигурные скобки оставляют значение без экранирования,
   комментарии и отсутствующие значения ничего не выводят.
2. **Вложенные `if/else`.** Вложенные условные блоки выбирают правильную ветку
   и корректно закрываются.
3. **Контекст `each`.** В цикле работают `this`, доступ к полям элемента,
   `@index` и обращение к значению корневого объекта.
4. **Вложенные циклы.** Поддерживаются циклы внутри циклов и ветка `else` для
   пустой коллекции.
5. **Правила истинности.** Ноль и пустой массив считаются ложными, объект —
   истинным.
6. **Структурные ошибки.** Несовпадающие открывающий и закрывающий блоки
   приводят к ошибке с номером строки и столбца.
7. **Объект нельзя вывести как скаляр.** Попытка обычной подстановки объекта
   завершается ошибкой.
8. **README.** В проекте есть содержательный `README.md`.

## HTTP KV

[Спецификация](./projects/http-kv/SPEC.md) ·
[код проверок](./scripts/evaluate.ts#L332)

Перед проверками сервер запускается на случайном локальном порту и должен
сообщить его строкой `LISTENING <port>`. Хранилище размещается во временном
файле, который затем используется для проверки перезапуска.

1. **Health endpoint.** `GET /health` отвечает кодом 200, JSON
   `{"status":"ok"}` и корректным `Content-Type`.
2. **Создание, замена и URL-декодирование ключа.** Первый `PUT` возвращает 201,
   повторный — 200, последующий `GET` выдаёт новое значение и декодированный
   ключ с пробелом.
3. **Сортированный список живых ключей.** `GET /v1/keys` возвращает ключи в
   лексикографическом порядке.
4. **TTL.** Ключ с коротким временем жизни исчезает как из `GET`, так и из
   списка ключей.
5. **Ошибочные запросы.** Повреждённый JSON и недопустимый TTL дают ответы
   класса 4xx; ошибка JSON сама представлена JSON-объектом.
6. **Удаление.** Первое удаление существующего ключа возвращает 204, повторное —
   404.
7. **Сохранение после перезапуска.** Обычный ключ остаётся доступным после
   остановки и нового запуска сервера, истёкший ключ не восстанавливается.
8. **Маршруты и методы.** Неизвестный путь возвращает 404, неподдерживаемый
   метод существующего endpoint — 405.
9. **README.** В проекте есть содержательный `README.md`.

## Dependency Planner

[Спецификация](./projects/dependency-planner/SPEC.md) ·
[код проверок](./scripts/evaluate.ts#L419)

1. **Детерминированный план.** Для связанного графа одновременно проверяются
   топологический порядок, параллельные слои, ранние времена старта и окончания,
   общая длительность и критический путь.
2. **Разрешение равенства.** Если существует несколько критических путей
   одинаковой длины, выбирается лексикографически минимальный.
3. **Пустой граф.** Возвращаются пустые порядок, слои, расписание и критический
   путь, а общая длительность равна нулю.
4. **Детерминированное описание цикла.** Циклический граф отклоняется, сообщение
   содержит конкретный путь вида `a -> b -> a`.
5. **Неизвестная зависимость.** Ссылка на отсутствующую задачу приводит к
   ошибке с её идентификатором.
6. **Проверка схемы.** Повтор одной зависимости и отрицательная длительность
   отклоняются.
7. **README.** В проекте есть содержательный `README.md`.

## Общие свойства запуска

- Проверки работают с проектом как с чёрным ящиком и вызывают его через
  заявленный CLI или HTTP API.
- Для каждого проекта создаётся отдельный временный каталог с тестовыми данными.
- Один внешний процесс по умолчанию ограничен 20 секундами.
- Ошибка одной проверки записывается в результат, после чего оценщик продолжает
  остальные проверки задачи.
- Итоговый JSON содержит название каждой проверки, признак прохождения и
  диагностическое сообщение для неудачи.
