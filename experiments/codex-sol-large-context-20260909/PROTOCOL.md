# Sol: повторение конфигурации с лимитами 2 MiB

Протокол до вызовов модели, 2026-09-09. Новая серия после завершённой
[Astra с большими лимитами](../codex-astra-large-context-20260908/PROTOCOL.md).
Используем тот же бинарник, не пересобираем и не меняем ядро.

## Условия

- gpt-5.6-sol, reasoning medium, прежняя авторизация; без сбросов лимитов.
- Native / Paper / V2 / V3: по пять повторов пяти прежних проектов —
  100 сессий, по 25 на режим и 200 исходных assertions на режим.
- До пяти основных CLI одновременно. Вспомогательный permission reviewer
  остаётся включён; его обращения не смешиваются с основными.
- Таймаут 900 000 мс. Те же one-shot инструкции, SPEC и независимый оценщик.
- То же заранее определённое чередование проектов и режимов, что у Astra.
  Новые workspace и идентификаторы сессий; outcomes не переиспользуются.
- Все четыре режима используют один бинарник SHA-256
  6c573e7f919cce1968def7ec067afbcdf3f2b4a76c7811178ac5715ac84997ee.
  Code Mode companion SHA-256:
  b5ce3a2a9d1c65389c5fb32fa2b734251b644929d039cf4867683d39a90b9630.

Лимиты SKILL.state — по 2 097 152 байта на полный JSON state, принимаемый input
одного действия, сохраняемый input и сохраняемый result. Это не общий бюджет
промпта и не размер окна модели. Comment остаётся ограничен 1 KiB.
Сохраняется поправка из Astra: JSON перехода не разрезается повторной обрезкой
истории; это history metadata, которая не добавляется в prompt.

Paper использует только последнее наблюдение; V2/V3 — k=3.
Один V3-батч занимает один слот, число действий не ограничено. Текст протокола,
схемы, patch, finish, инструментальные и провайдерские лимиты не меняются.
Штатный Native остаётся Native. Модель может сама запросить малый max_output_tokens:
увеличение наших лимитов не отменяет такую обрезку.

## Изоляция и остановка

Повторяем тот же механизм временного перемещения глобальных skills,
skills в кэше плагинов и глобальных AGENTS.md / AGENTS.override.md.
Точные существующие пути определяются перед запуском; количество может
отличаться от Astra из-за обновлений плагинов. Авторизацию и конфигурацию
не редактируем. Приватный write-ahead ledger сохраняет права и отпечатки.

Флаги прежние: --ignore-user-config, --ignore-rules, отключённый skill_search,
skills.include_instructions=false, skills.bundled.enabled=false,
project_doc_max_bytes=0, --approve-for-me.
Источники проверяются перед каждым запуском, после исхода и каждые две секунды.
Допускается только повторное появление отключённого скрытого .system-кэша
в обычном каталоге ~/.codex/skills; другие источники и ссылки останавливают серию.

Файлы возвращаются после остановки всех воркеров, включая обрабатываемые ошибки
и сигналы; новые файлы на прежних местах сохраняются отдельно.
После SIGKILL/перезагрузки сначала нужно остановить оставшиеся воркеры,
затем восстановить источники по указателю .private/isolation.json.
Не удалять ledger, run.json и manifests ради нового запуска.

Нет автоматических повторов неудачных outcomes, best-of или исключения таймаутов.
Ошибки авторизации/лимитов, отсутствующий usage, несоответствие фактической модели,
повреждённые переходы и загрязнение начального контекста останавливают выдачу задач.
Обычные таймауты и неуспешные решения остаются результатами.

## Проверки и сравнение

До запуска сверяем завершение и восстановление Astra, замороженные исходники,
бинарник и companion. Проверки ядра 18/18 и доступные CLI-проверки 7/7
переиспользуются как свидетельства именно этой неизменной сборки, а не
выдаются за новые тесты. Ограничение shell-фикстуры, описанное в
[Astra preflight](../codex-astra-large-context-20260908/preflight.json), сохраняется.
Заново проверяем локальный runner-контракт, расписание, изоляцию, pool, аудит
и doctor. Полное расписание и source manifest фиксируются до первого запроса.

Для каждой сессии сохраняем исходные assertions, main input (cached уже входит),
output, число ответов, время, таймаут, exit и finish/turn.completed.
Полный успех требует и корректного артефакта, и штатного завершения протокола.
Числовой аудит сверяет usage, фактическую модель, размеры полей и маркеры обрезки;
начальные сообщения проверяются на скиллы и глобальный профиль.
Это аудит rollout, не перехват всех provider-visible запросов.

В итоговом разборе известная проверка taskboard delete применяется отдельно
к копиям всех CLI-артефактов. Исходный оценщик и оценки не переписываются.
Вспомогательные вызовы учитываются отдельно. Время таймаута не называется
временем решения, количество assertions — числом независимых задач.

Сравниваем четыре режима внутри серии и отдельно — с
[чистой Sol со старыми лимитами](../codex-sol-clean-20260908/PROTOCOL.md).
С Astra сравниваем ту же конфигурацию и число повторов, но это разные модели
и даты запуска. Увеличение четырёх лимитов и сохранение JSON не разделены:
это не абляция каждого фактора и не доказательство причинного эффекта.

Старые данные, журналы и статья не меняются. Raw logs остаются в игнорируемой
.private/; публичный очищенный снимок и обновление статьи — отдельные действия.
