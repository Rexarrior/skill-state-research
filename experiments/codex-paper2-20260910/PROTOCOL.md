# Paper2: последнее действие вместе с результатом

План зафиксирован 10 сентября 2026, до новых вызовов моделей. Это отдельная серия
Codex: Sol и Astra, пять повторов пяти прежних проектов — всего 50 сессий.

## Что меняется

При повторном аудите стало понятно, что результат среды O в исходной статье может
сам описывать выполненное действие. Первый Paper-адаптер не добавлял эту информацию
к ответу инструмента; при пустом stdout она терялась. Это выбор нашего адаптера,
а не обязательное ограничение SKILL.state. Paper2 проверяет более содержательное
последнее наблюдение, не добавляя историю.

Контракт ответа остаётся Paper: ровно `state_patch` и `action`, рекурсивное слияние
с null-удалением, та же coding schema, проверка → patch → одно действие. Модель
не передаёт `comment`, `state_revision` или батч. Завершение — только `finish`.
P, основной текст инструкции и tool schema остаются прежними.

Единственное изменение модельного контекста относительно Paper той же большой сборки:

```json
{
  "action": {"name": "exec_command", "input": {"cmd": "bun test"}},
  "status": "success",
  "result": "12 tests passed"
}
```

Всегда передаётся только одна последняя запись, даже если настройка окна больше одного.
Runtime формирует поля действия и статуса из фактического вызова; комментариев нет.
Локальная история остаётся для аудита/resume, но не отправляется модели.
Режим: `CODEX_SKILL_STATE_MODE=paper2`; идентификатор перехода `skill.state/paper2`.
Состояния другого режима не принимаются за Paper2 при восстановлении.

Это не V2 с k=1: мы не переносим её revision, comment или top-level replacement.
Это также не полное воспроизведение авторской среды: собственная schema, typed tools,
упаковка P и Native/Code Mode остаются ранее раскрытыми адаптациями.

## Сборка и условия

- Отдельный detached worktree от `85630a5b6d89465ed52cdb0ad56eec15f07fdfae`,
  с patch расширенных лимитов и новым Paper2. Старые источники и бинарники не меняются.
- Сохраняются четыре лимита по 2 МиБ и защита JSON истории. Внутренние ограничения
  инструментов, включая заданный моделью `max_output_tokens`, не отключаются.
- Модели `gpt-5.6-sol` и `gpt-6-astra`, reasoning medium, 15 минут на сессию.
- Пять прежних SPEC, неизменный one-shot prompt и внешний оценщик.
- До пяти основных CLI одновременно на обе модели суммарно. Permission reviewer
  остаётся включён; лимит CLI не гарантирует столько же внутренних provider requests.
- Заранее определённое чередование моделей и задач, пять повторов без выбора
  лучших попыток. Таймауты, ошибки кода и незавершение остаются исходами.
- Ошибки лимитов/авторизации/модели, отсутствие usage, повреждение перехода
  или загрязнение стартового контекста останавливают новые запуски.

## Изоляция и восстановление

Используются проверенные helpers предыдущей чистой Sol-серии: временное перемещение
глобальных skills, skills кэша плагинов и глобальных AGENTS-файлов, write-ahead журнал,
проверки источников каждые две секунды и перед запуском, возврат после завершения
или обработанного сигнала. Вновь созданные файлы сохраняются отдельно, не удаляются.
Авторизация и конфигурация не редактируются. Те же CLI-настройки отключают глобальные
инструкции, bundled skills и skill_search. Это не полная изоляция ОС.

После SIGKILL/перезагрузки нельзя заново запускать `run.ts`: сначала проверить
`run.json`, активные процессы и `.private/isolation.json`, восстановить источники
по указанному ledger. Автоматического повторения исходов нет.

## Проверки и сравнение

До запуска: unit tests admission/merge/последнего O/изоляции протоколов/большого JSON,
CLI mock-provider, проверка native и прежнего Paper, тесты расписания и helpers,
format, scoped Clippy, doctor и отпечатки исходников/сборки.
Известные недоступные shell-fixtures указываются отдельно, не считаются прошедшими.

Сохраняются input с cached как подмножеством, output, число основных обращений,
время, исходные проверки, exit/timeout и accepted finish. Полный успех требует
всех проверок и штатного завершения. Известную поправку taskboard delete следует
проверить отдельно на копиях артефактов, не переписывая исходный score.
Публичный отчёт не содержит сырых промптов, рассуждений, tool output и авторизации.

Сравнивать будем прежде всего с [последними сериями на расширенных лимитах](../codex-large-context-comparison-20260909/README.md),
отдельно для каждой модели. Они проведены раньше: здесь нет новых одновременно
рандомизированных Native/Paper/V2/V3-контролей. Поэтому это уточняющий инженерный
эксперимент, а не окончательная оценка причинного эффекта формата O. Имя, аргументы
и статус добавляются пакетом; их индивидуальный вклад тоже не разделён.
