# Paper2: продолжение после обновления кэша

Продолжение разрешено пользователем 10 сентября 2026. Ядро, бинарник, runner,
модели, лимиты, SPEC и оценщик остаются прежними. Исходный сегмент и его manifest
не переписываются. Новые изменения относятся только к оркестрации и восстановлению.

Четыре завершённых исхода переносятся без отбора по качеству, после проверки
сохранённых аудитов стартового контекста и usage. Это включает исход Sol 7/8.
41 ячейка ещё не запускалась. Пять внешне прерванных попыток сохраняются отдельно;
пользователь разрешил новые попытки с чистыми рабочими каталогами и новыми ID.
Итого продолжение запускает 46 сессий, чтобы получить 50 целевых исходов.
Это не означает всего 50 физических попыток: с пятью прерванными их будет 55.
Расход незавершённых попыток нельзя выдавать за нулевой; при итоговом анализе
их нужно учитывать отдельной инфраструктурной строкой по доступным журналам.

## Исправления

- Состояние остановки сохраняется до восстановления, а его финальный статус —
  даже при исключении во время возврата источников.
- Исчезнувшие родительские каталоги старой версии создаются заново. Новые версии
  не перезаписываются; пересозданные оригиналы сохраняются отдельно.
- Возврат пытается обработать все источники, собирая ошибки отдельных элементов;
  частичный возврат не помечается успешным.
- Guard остаётся строгим: появление активного источника останавливает новые
  запуски и прерывает работающие CLI. Никаких скрытых retries или игнорирования
  новых скиллов. Следующее прерывание потребует отдельного решения о продолжении.
- До пяти CLI на обе модели суммарно. Новая инвентаризация временно перемещает
  также появившиеся версии скиллов; контроль выполняется каждые две секунды.

Завершённые исходы проверяются по записанным сообщениям и числовым аудитам,
не по сетевому захвату всех запросов. Смена кэша — дополнительная граница окружения
между сегментами; её нельзя скрывать в описании методики.

## Артефакты

`resume.ts` пишет только `run-resume-1.json`, `source-manifest-resume-1.json`,
`isolation-watch-resume-1.json`, `restoration-resume-1.json` и новые приватные логи
в `.private/resume-1`. Исходный `runner.ts` создаёт результаты с новыми UUID
в прежнем `.private/results`, не перезаписывая старые.
`progress.ts` показывает продолжение, если его checkpoint уже существует.
После SIGKILL сначала проверить процессы и `.private/resume-1/isolation.json`,
затем выполнить восстановление через `isolation-resume.ts` с указанным ledger.
